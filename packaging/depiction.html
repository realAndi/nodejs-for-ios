Node.js

Current Node with npm, npx and working nvm, patched for iOS

A real, current Node.js on your phone. npm install, npx, node:sqlite, WebAssembly, HTTPS and nvm install all work.

What gets installed

Not a cross-compile. The official darwin-arm64 build from nodejs.org imports 725 symbols and iOS is missing exactly three of them, so this downloads Apple's own build and patches it: the Mach-O is restamped to claim platform iOS, the CoreFoundation and Security load paths are rewritten to the flat iOS layout, and a 68 KB shim is linked in for the rest.

The tarball is checked against the SHA-256 this package was built against before anything is patched, and the patcher refuses a build that links a dylib iOS lacks. About 50 MB downloaded, 220 MB installed.

How the JIT works

iOS rejects MAP_JIT with EINVAL and kills a process that executes a writable page, but it will let mprotect swing a page between read-write and read-execute. And pthread_jit_write_protect_np, the call V8's arm64 Darwin build uses to flip its code pages, does not exist on iOS at all.

So the shim strips MAP_JIT, remembers the region, and implements the flip with mprotect. That is process-wide where the real API is per-thread, so the shim also forces V8 --single-threaded from a library constructor — the one route that survives a #!/usr/bin/env node shebang and anything npm spawns.

Using nvm

Install nvm as usual, then add one line to your shell profile:

. /var/jb/usr/local/lib/node-ios/nodeios.sh

It fixes nvm's architecture detection — iOS uname -m answers the device model, so stock nvm asks nodejs.org for a darwin-iPhone16,1 build and falls back to a source compile that cannot work — and patches each version nvm install brings down.

Requires

  • A rootless jailbreak (/var/jb) — tested on Dopamine
  • iOS 15 or later, arm64 — tested on iOS 17.3 (iPhone 15 Pro)
  • Network at install time, for the ~50 MB download
  • Depends: zsh, bash, python3, ldid, curl, tar, coreutils — Sileo installs any that are missing.

Notes

  • Node 24 and newer only. Node 23 and earlier are built with a macOS deployment target of 11.0, so the linker emits classic LC_DYLD_INFO_ONLY bind opcodes rather than chained fixups, and this port has no opcode rewriter. nvm install 22 will download and then fail to patch.
  • worker_threads is reliable up to two workers. Past that the process-wide W^X flip races a worker isolate compiling against the main isolate executing, and the process takes SIGBUS. For worker-heavy work run with NODEIOS_V8_FLAGS=--jitless, which is slower but thread-safe. Eight workers pass reliably that way.
  • Native addons need patching too. A prebuilt .node from npm is a macOS dylib. Run node-ios-patch on it, or expect it to fail to load.
  • /bin/sh does not exist on a rootless jailbreak and Node hard-codes it for shell: true. The shim remaps /bin, /usr/bin and friends into /var/jb, but only when the original really is missing.
  • Node's --use-system-ca is inert: the macOS keychain API behind it does not exist on iOS, so the shim reports "no trust settings" and Node keeps its bundled Mozilla roots. Ordinary TLS is unaffected.
  • Replaces io.github.imcynic.nodejs if you have it.
